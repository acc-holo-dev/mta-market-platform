# PROJECT — MTA Market

Обновлено: 2026-09-11 (после выполнения PLAN-010).

Этот документ описывает текущее состояние MTA Market с точки зрения продукта.
Это не roadmap и не task list — развитие проекта ведётся через
[Development Plan system](DEVELOPMENT/README.md).

---

## Что такое MTA Market

MTA Market — единая цифровая площадка сообщества Multi Theft Auto: San Andreas:
сообщество (форум, новости), серверы (профили, мониторинг, верификация),
контент (статьи — целевое состояние), маркет ресурсов и услуг, доверие
(отзывы, верификации, гарантии — частично) и идентичность (профили, бейджи).

Формулировка-якорь: MTA Market **не** «магазин ресурсов с немного community».
Центральная сущность после PLAN-005 — **SERVER**: у сервера есть страница,
онлайн-статус, новости, обновления, сообщество и отзывы с подтверждением
взаимодействия. Коммерция (маркетплейс ресурсов) — одна из опор экосистемы,
а не вся платформа.

Честная формулировка DRM: защита **повышает стоимость массового копирования**
и делает лицензии контролируемыми и атрибутируемыми; это не абсолютная защита
от декомпиляции. Покупка ≠ платёж ≠ лицензия — это разные сущности с разными
машинами состояний.

## Основные части системы (уже существуют)

### Идентичность и профиль
- **Аутентификация**: локальная регистрация/вход (username или email + пароль, bcrypt),
  OAuth (Discord/Yandex/Google), связывание идентичностей, JWT access + refresh-ротация
  в HttpOnly cookie, детекция переиспользования refresh-токена, logout.
- **Профиль и баланс**: отображаемое имя/аватар; публичный профиль `/profile/[username]`
  с бейджами и публичными серверами/ресурсами (email/баланс/покупки — приватны);
  баланс пользователя — реальная строка в БД (`userBalance`, копейки/RUB).
- **Один User — много ролей**: один и тот же пользователь может быть продавцом,
  владельцем сервера и участником сообщества; отдельные аккаунты под роли не создаются.

### Серверы (с PLAN-005)
- **Server domain**: модель Server (slug, владелец, брендинг, приватные
  connection-данные, lifecycle CREATED → PENDING_VERIFICATION → VERIFIED → ACTIVE,
  + SUSPENDED/ARCHIVED), staff-роли (ServerMember).
- **Регистрация**: мастер `/servers/create` (Basic → Connection → Branding →
  Visibility → Verification).
- **Ownership verification**: possession-токен интеграции; первый валидный
  heartbeat от модуля/скрипта → VERIFIED (audit + уведомление).
- **Публичная страница** `/servers/[slug]`: hero с онлайн-статусом, разделы
  Обзор/Live/Статистика/Новости/Обновления/Отзывы/Сообщество.
- **Мониторинг**: ONLINE/OFFLINE/UNKNOWN из реальных heartbeat-сэмплов;
  тишина деградирует в UNKNOWN (никогда не «врёт» OFFLINE); статистика
  peak/average/uptime за 24h/7d/30d считается по реальным сэмплам.
- **Приватность by default**: host/port не покидают бэкенд; флаги
  showResources/showStaff/showTechStack/showCommunity выключены по умолчанию;
  связь Server↔Resource публична только по явному opt-in владельца —
  enforcement на backend-authorization layer, не в UI.

### Сообщество (с PLAN-005)
- **Глобальный форум** `/community`: категории, темы, посты, реакции,
  редактирование, мягкое удаление, состояния OPEN/LOCKED/ARCHIVED, pin,
  реальные просмотры; темы могут быть привязаны к серверу (server-centric
  discussions) — привязка только персоналу сервера.
- **Новости серверов**: черновик → публикация (уведомления подписчикам),
  опциональное обсуждение (один тред на новость); глобальная лента `/news`;
  **обновления** серверов с версией и changelog.
- **Follow & notifications**: подписка на сервер, счётчик подписчиков, центр
  `/notifications` (SERVER_NEWS / SERVER_UPDATE / FORUM_REPLY / REVIEW_EVENT /
  MODERATION), колокольчик с непрочитанными.

### Контент (с PLAN-007)
- **Статьи**: DRAFT → PENDING_REVIEW → PUBLISHED/ARCHIVED; модерация с
  причиной (audit + уведомление автору), репорты ARTICLE; хаб /content
  (категории, пагинация), страницы статей с явными связями
  (ресурсы — любые PUBLISHED; серверы — только staff) и тредами
  обсуждения; «Мои статьи» у автора; профиль автора показывает публикации.
- **Интеграция в экосистему**: NEW_ARTICLE в активности Home, группа
  Articles в поиске, «Статьи» в навигации.

### Daily Experience (с PLAN-006)
- **Живой Home**: «Сейчас в MTA» (глобальные LIVE-агрегаты игроков/серверов
  онлайн из реальных heartbeat-сэмплов), лента «Активность» (9 типов
  высокоценных событий с deep links), «Популярное» (топ серверов по реальному
  онлайну, горячие обсуждения); маркетплейс-секции сохранены. Всё доступно Guest.
- **Activity read-layer**: derived-агрегация поверх существующих доменов
  (server news/updates, ресурсы/версии, форум, отзывы) — окно 7 дней,
  bounded queries, кэш с инвалидацией на публикациях; без новой доменной
  сущности и без приватных событий.
- **Dashboard «Сейчас / За ночь»**: сводка с момента последнего визита
  (подписки, обсуждения, покупки, уведомления) с deep links.

### Доверие (частично)
- **Отзывы на ресурсы** — после покупки (PLAN-001).
- **Отзывы на серверы** (с PLAN-005): только после claim одноразового
  review-токена интеграции (server-bound, срок, replay-protection,
  self-review ban, один отзыв на пользователя); метка «✓ Verified Interaction»
  означает подтверждённое взаимодействие, а не оценку содержания.
- **Верификации**: Verified Server (ownership), Verified Seller, бейджи
  с критериями и audit-источником.
- Гарантии/deals, trust hub, blacklist — целевое состояние (см. VISION),
  ещё не реализованы.

### Follow-система (с PLAN-008)
- **Подписки**: сервер (PLAN-005), создатель (продавец с APPROVED профилем),
  ресурс (PLAN-008), тема обсуждения (PLAN-009). Уведомления о релизах,
  обновлениях версий, статьях создателя и ответах в отслеживаемых темах;
  покупатель уведомляется об обновлении купленного. Только агрегаты —
  списки подписчиков не публикуются.

### Аналитика создателя (с PLAN-010)
- **Просмотры и конверсия**: открытия страниц ресурсов агрегируются
  (ресурс × день, без идентичностей зрителей); продавец видит просмотры за
  30 дней, покупки и конверсию по каждому ресурсу в своём кабинете.
  Просмотры — приватные данные продавца (не публичная метрика).

### Коммерция
- **Маркетплейс**: каталог опубликованных ресурсов с фильтрами, карточка ресурса
  с версиями и отзывами; медиа ресурсов (обложки, скриншоты, валидация, оптимизация).
- **Seller flow**: заявка → одобрение админом → кабинет → мастер создания ресурса
  (инфо → тип/цена → artifact → модерация); витрина продавца `/sellers/[username]`.
- **Artifact pipeline**: загрузка архива, SHA-256, строгая валидация (статический анализ
  содержимого ZIP), Ed25519-подпись артефакта платформой, версии релизов
  (CANDIDATE → VERIFIED → PUBLISHED, yank).
- **Модерация**: очередь `PENDING_REVIEW`, approve/reject с причиной; append-only
  `moderationEvent` + audit trail; репорты пользователей (посты/темы/отзывы/серверы/
  новости) с очередью модерации и решениями.
- **Коммерция**: checkout создаёт Order + OrderItem + Purchase; бесплатный ресурс
  завершается сразу; платный — через ЮKassa (webhook) или dev-completion; лицензия
  после завершения; скидки/промокоды с неизменяемым снимком строки заказа; услуги
  (services) с заказами, доставкой и спорами.
- **Финансовый ledger**: двойная запись, платформенная комиссия и выплата продавцу,
  reconciliation-джобы.
- **DRM v2**: Ed25519-подписи, challenge → installation → activate → lease (7 дней),
  DEK aes-256-gcm, rotation ключей. Сервер — в `mta-market-site`, клиент — в
  `mta-market-module/source/drm/`.

### Интеграция игровых серверов (с PLAN-005)
- **Протокол**: `POST /integration/heartbeat` (только агрегаты: статус, онлайн,
  слоты) и `POST /integration/review-tokens` (одноразовый токен игроку).
- **Модуль**: `mta-market-module/source/drm/market_client.{hpp,cpp}` + Lua-функции
  `mta_market_*`. Privacy: модуль передаёт только счётчики; player identity,
  IP, чат и телеметрия не собираются.

## Как взаимодействуют роли

**Player (игрок / гость)**
1. Приходит на `/servers`, находит сервер, открывает страницу: онлайн, статус,
   новости, отзывы.
2. Подписывается на сервер → получает уведомления о новостях и обновлениях.
3. В игре получает review-токен от серверной интеграции → вводит его на странице
   сервера → оставляет отзыв с меткой Verified Interaction.

**Community Member (участник сообщества)**
1. Открывает `/community`, читает категории и темы.
2. Создаёт тему или отвечает, реагирует, подписывается, репортит нарушения.
3. Получает уведомления об ответах; возвращается через дашборд.

**Server Owner (владелец сервера)**
1. Регистрирует сервер через `/servers/create`, подтверждает владение
   интеграционным токеном (heartbeat от модуля или dev-скрипта).
2. Оформляет страницу (брендинг), управляет приватностью (что публично),
   подключает мониторинг.
3. Публикует новости и обновления, создаёт server-linked обсуждения,
   видит отзывы и подписчиков в `/servers/[slug]/manage`.

**Buyer (покупатель)**
1. Ищет ресурс в Marketplace, фильтрует, открывает карточку.
2. Бесплатный — «Получить»; платный — оплата через ЮKassa.
3. Видит покупки и лицензии в аккаунте, оставляет отзыв после покупки,
   может открыть спор.

**Seller (продавец)**
1. Подаёт заявку «Стать продавцом»; админ одобряет.
2. В кабинете создаёт ресурс через мастер; ресурс уходит в `PENDING_REVIEW`;
   результат модерации виден в кабинете.

**Admin (админ/модератор)**
1. Admin Panel: модерация ресурсов, одобрение продавцов, споры, yank версий.
2. Серверы: inspect, verify/reject, suspend/restore/archive — каждое действие
   с audit-записью и уведомлением владельцу.
3. Жалобы: очередь → resolve/dismiss; модерация контента сообщества
   (news/reviews/threads); отзывы скрываются с audit.

## Реализованные бизнес-сценарии

1. Регистрация → вход → профиль → баланс → сессия переживает reload.
2. Player: `/servers` → страница сервера → онлайн/новости/отзывы → follow →
   уведомление о новости.
3. Server Owner: создание сервера → верификация heartbeat-токеном → публикация →
   мониторинг → новость → уведомления подписчикам.
4. Community: категория → тема → ответ → реакция → репорт → модерация.
5. Review-token: выпуск токена интеграцией → claim → отзыв с Verified Interaction;
   просроченный/переиспользованный/чужой токен отклоняется.
6. Продавец: заявка → одобрение → создание ресурса → artifact → `PENDING_REVIEW` →
   модерация → публикация.
7. Покупка: бесплатное получение и платная покупка (payment → `COMPLETED` +
   license `ACTIVE`); спор по покупке; услуги с заказами и доставкой.
8. DRM-жизненный цикл: entitlement → installation → challenge → activate → lease.
