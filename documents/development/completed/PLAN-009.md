=================================================
0. ЦЕЛЬ PLAN-009
   ==================================================

Переход состояния:

ИЗ:

Community Loop (DAILY-EXPERIENCE §10) разорван на шаге Follow: подписаться
можно на сервер/создателя/ресурс, но не на обсуждение. Получатели FORUM_REPLY
— только автор темы и те, кто уже ответил. «Молчаливый читатель» — самый
массовый тип участника сообщества — не имеет возвратного канала.

В:

Пользователь следит за любым обсуждением (Follow на странице темы) и получает
уведомление о каждом новом ответе; сводка «Сейчас / За ночь» показывает
ответы в отслеживаемых темах. Порядок follow-модели §16 доведён до Thread
(остаётся Community — осознанно отложено, см. §6).

После PLAN-009:

читатель открывает интересную тему
→ Follow
→ читает дальше, уходит
→ кто-то отвечает
→ уведомление с deep link
→ возвращается и участвует.

=================================================
1. СТРАТЕГИЧЕСКАЯ ИДЕЯ
   ==================================================

План не называется:

"Notification improvements".

Суть — завершить петлю сообщества: чтение должно превращаться в
возвращение даже без участия. Подписка на тему — самый дешёвый и самый
честный механизм: пользователь сам сказал, что тема ему интересна.

Никаких алгоритмов «вам может понравиться» — только явный Follow.

=================================================
2. ПРИНЦИПЫ
   ==================================================

1. Приватность (§42): follower identities никогда не публикуются — только
   агрегат-счётчик на странице темы; список подписчиков не существует.
2. Follow — приватная relationship: не попадает в activity layer
   (PLAN-006 не расширяется).
3. Уведомление — существующий тип FORUM_REPLY (новый тип не нужен):
   «Новый ответ в теме «...»» уже несёт всё (что произошло / deep link).
4. Dedup: участник, одновременно являющийся подписчиком, получает ровно
   одно уведомление (createNotifications dedup по получателю).

   =========================

- **Community follow** (последний шаг §16): в платформе пока нет сущности
  «сообщество» как объекта подписки (глобальный форум един; серверные

- Изменения в существующих получателях FORUM_REPLY (автор + участники)
  сохраняются как есть.

## Уроки окружения (дополнение)

1. **Оркестрация фоновых задач**: pkill по строке, совпадающей с собственной
   командой, убивает свой же процесс (build-джоба была убита собственным
   pkill); E2E-прогон нельзя прерывать перезапуском серверов — порядок:
   прогон → стоп → build → рестарт дев-серверов.
2. **URL-схема форума**: API-путь треда — `/community/threads/:id`
   (detail/reply), а surface-путь — `/community/forum/thread/:id`. Для
   follow использован surface-путь (`/community/forum/thread/:id/follow`),
   чтобы совпадать с элементом страницы; это осознанное исключение из
   API-схемы, задокументировано здесь.
